# Lyric Video Studio

Render a whole song as kinetic typography driven by code: a segment table (one row per lyric line) drives one 1920x1080 frame per 1/30 s, Pillow draws every glyph, ffmpeg muxes the original audio back on. Nothing is generated by a video model, so every frame is deterministic, diffable, and re-renderable -- which is what makes a single bad page cheap to repair.

## Deliverable contract
- 1920x1080, 30 fps CFR, H.264 High profile, CRF 16, yuv420p, AAC 192k stereo, `+faststart`, full song length.
- One segment (page) per lyric line; a shot change every 1-2 lyric lines, each landing on a musical onset.
- Two-colour discipline unless the style calls for accents: backgrounds only from a 2-3 colour palette (the reference case used exactly rgb(10,10,10) and rgb(247,247,243)) with one accent (朱砂 rgb(176,48,40)) for emphasis.
- Everything on screen is typeset from strings. No stock footage, no AI-generated bitmaps, no bitmap fonts.
- Ship a manifest next to the video: `frame k <-> song time T0 + k/FPS`, plus the container-time offset of the delivered file (see pitfalls: mux offset). `scripts/delivery_manifest.py` generates it (song facts, both deliverables' frame<->song mapping, the chunk partitions, and a per-page table carrying each page's official LRC stamp).
- Ship the chunk manifest too whenever the song is rendered in chunks, and prove the assembly
  (`scripts/verify_assembly.py`). A chunked render that is not verified can ship a film whose picture
  is silently time-shifted against its own audio -- see references/assembly.md.
- A second, vertical deliverable (1080x1920 short for short-form platforms) is built from the SAME
  parts as the landscape film -- one renderer core, one timing authority, a window switch in the data
  layer -- never by copying the film module. Its format is 1080x1920, 30 fps CFR, H.264 High CRF 16,
  yuv420p, AAC 192k, with an intentional head/tail; see references/renderer.md section 1 and
  references/pipeline.md for the windowed envelope. Verify it with `scripts/verify_short.py`, which
  reads the delivered short (not the renderer) and checks streams, frame count, container order,
  vendor-tag hygiene, audio offset against the decoded song, per-frame pixels, and every chunk seam.

## Non-negotiables
0. **Decide the timing authority before you build anything.** If more than one LRC exists, score them against the decoded audio (`assets/timeline_gen.py score`). Two files with identical text can sit most of a second apart -- the reference case had one exactly 0.850 s early -- and a film built on the wrong one is a full re-timeline. Then DERIVE the page table from rules and assert the rule invariants (`assets/timeline_gen.py build`). Never hand-author a cut list or a page-index table: hand-edited tables do not converge (45/47/48/50/51 pages across six fix attempts, and one write round-trip silently truncated a 49-entry cut list to 42).
   **When the two files differ by ONE uniform offset, no acoustic test can separate them.** Measured on the 心月灯 project: two files, 40 identical lines, every stamp differing by exactly -2.175 s. Strongest-attack-in-+-3 s, a log-frequency spectrogram overlay, phrase-gap detection and a pre/post breath statistic were all inconclusive, because a wall-of-sound mix has ~4 onsets a second and fills the vocal band continuously. In that case: state the evidence you have, ASK the user, back the timeline inputs up to one directory (`_lvstmp/tl_<name>/`) so the revert is a copy plus a re-render, and then commit to their choice. Diagnostic tell that a grid is early: when every refit can only push cuts LATER (all deltas >= 0, several clamped at `MAXMOVE`, none able to move back), the grid is systematically early by roughly that amount -- report it, do not silently "fix" it.
1. Run the collision audit BEFORE rendering and again BEFORE delivering, and make sure it is an audit of what the renderer actually draws:
   - if the film computes its own plan, `scripts/layout_audit.py film.py --from-layout --require-deco` (legacy mode reads the template's SEG field names and would grade a fiction);
   - decorations must be in the box set (`deco_boxes`), because a decoration that the audit cannot see can cover any glyph;
   - it must print `remaining box collisions: 0` and report no out-of-canvas boxes.
   Both false greens are on record: a legacy-field audit against a `layout()`-based renderer, and a text-only audit blind to decorations -- each printed `0` while the delivered frame had strokes across the headline.
   **A clean audit is still not a picture.** The audit proves boxes do not intersect; it cannot see that the lyric is drawn upside down, that a mask was clipped square behind the headline, or that a shape reads as a grey card. Render every page cheaply (`film.py --pages 0-46 --out preview` -> `scripts/contact_sheet.py`) and LOOK at the sheet before the full render, and again after muxing. Every pixel-level defect in the reference projects was found this way and none of them by a verifier.
2. Measure fonts, never trust their names. Use `d.textlength()` for advance width and an ink-bbox probe for ink height. Ascent/descent metadata lies. Measure per face with a nonzero-pixel bbox for collision boxes: the reference CJK faces run 0.83-0.87 em above the baseline and 0.19-0.31 em below at sizes 20-48; the tighter `> 40/255` threshold under-reports the bottom by ~0.14 em. Round coefficients UP to the next 0.005 and never mix the two conventions in one layout.
3. Never place a second text block at a guessed y. Derive it from the measured bottom of the block above it.
4. Reserve space, do not clamp into it: give the code panel one column and the display line another, and keep decorations in bands the text column cannot reach. A clamp cannot create room -- one project walked a collision count 35 -> 25 -> 28 -> 27 -> 17 across a day of nudging and reached 0 only after the layout became an explicit two-column allocator. Order of concessions when a page is genuinely tight: tighten line spacing (to ~1.16, never stretch), move the caption to the running-head position, drop the decoration. Text is mandatory, decoration is bonus. After any refactor of the layout dispatcher, re-run the audit and a smoke render before trusting any other output -- a `return` one line too high silently disabled an entire layout pass while still returning a plausible plan.
5. Keep container metadata clean on mux: `-map_metadata -1` plus an explicit title, or the source audio metadata (e.g. a Bilibili XCoder tag) leaks into the deliverable.
6. Verify by reading the DELIVERED file, not the renderer: run `scripts/verify_delivery.py`
   (stream count, decoded frame count == NFR, `moov` before `mdat`, no foreign vendor tag in the
   metadata, audio-envelope lag, edge frames). A PNG out of the render module proves the renderer only.
7. Render long songs in chunks, but only with ONE canonical partition and an `out/chunks.json`
   manifest; never glob the chunk files. Verify the assembly (structure, pixel offset at pages that
   move, seams) before muxing. The reference case shipped 224 frames (7.4 s) of desync exactly here.
   **When the seam check flags a frame that is not a page cut, the FILM is jumping, not the assembly.**
   Diff consecutive frames rendered from the module (`scripts/diff_cell.py`) and compare them against
   the delivered file frame by frame (`scripts/seam_probe.py <mp4> <k0> <k1>`, which decodes by FRAME
   NUMBER via the `select` filter, never `-ss`, so a seek cannot be blamed). Page interior: 0.005-0.03
   mean|dL| per frame. A page change: 0.35+. Anything in between, on a frame that is not a boundary,
   is a renderer defect -- fix it and re-render; do not "repair" the mux.
8. Align the words to an authority: the platform's own LRC plus its translation track, kept read-only.
   Keep a `scripts/lrc_check.py` that checks text, the rendered reading ORDER, the time window and the
   stamp printed in the footer, and register every deliberate deviation in its `EXPECT` table.
9. One segment per lyric line, cuts on detected onsets, and **no card page may restate a neighbouring
   lyric in either language**. Two neighbouring pages must differ visually (polarity or decoration),
   or a correct hard cut still reads as a defect.
10. Measure motion, never argue for it: a continuous channel is measured on the steady tail of a page
    (`scripts/motion_probe.py`). Keep motion continuous -- a beat-locked binary toggle was reported as
    "闪来闪去，看得眼睛很不好受" and had to be deleted from the reference film.
    **A position breath on large type is not a continuous channel.** PIL rasterises glyphs on integer
    y, so a +-2 px breath steps the whole line by a full pixel twice per period, and that edge event
    (measured: 0.36 mean|dL| between consecutive frames) is LARGER than a page change -- the assembly
    verifier then reports a chunk seam at a frame that is not a cut, and the investigation hunts the
    encoder and the concat list instead of the renderer. Breathe in INK DENSITY
    (`fill = mix(fill, bg, max(0, amp))`) or in geometry that is not glyph rasterisation. Check with
    `scripts/diff_cell.py kA kB`: consecutive film frames on a page interior must stay under ~0.05
    (the HUD timecode alone is ~0.02).
11. Keep scratch files inside the project directory: under a file sandbox a child process is often
    denied writes to the platform temp dir, and `tempfile.mkdtemp()` picks exactly that path.
12. **Inputs are not output.** Anything you cannot regenerate -- the parsed `lrc_lines.json`, the
    derived `pages.json`/`cuts.json`, the envelope, the ground-truth LRC -- lives at the PROJECT ROOT,
    never in `out/`. `out/` holds only render artefacts (chunks, raw frames, concat lists, logs) that a
    re-render overwrites. Then "clear `out/` before a re-render" is safe, and it must be
    name-pattern-limited anyway:
    `Get-ChildItem -LiteralPath out -Force | Where-Object { $_.Name -match '^(film_|short_|chunks|list\.txt|run\d+\.log)' } | Remove-Item -Recurse -Force`.
    A blanket clear once deleted the page table, and all 8 render workers died in 0.4 s with
    `FileNotFoundError: ...\out\pages.json` -- after a 2-minute render had been queued.

## Pipeline
| Phase | Goal | Output | Detail |
|---|---|---|---|
| 1 Environment | python+Pillow+numpy, locate ffmpeg, pick fonts, check disk | working command line | references/pipeline.md |
| 2 Assets | song file, LRC (+ score competing LRCs against the audio), optional reference video | source inventory + the timing authority | references/pipeline.md |
| 3 Style | palette, grid constants, fonts, motion vocabulary | style spec + measured font table | references/forensics.md |
| 4 Timeline | LRC -> rule-derived page table (lyric page per stamp, cards only in real instrumental gaps), onset/bar check, audio envelope | TIMELINE.py-like tables + env_full.json | references/pipeline.md |
| 5 Renderer | grid + layers + per-page renderers + AA | film.py renders frames | references/renderer.md |
| 6 Transitions | 6 hand-built transitions, tested on a matrix | tr_matrix.png | references/renderer.md |
| 7 Render+mux | parallel frame render, ffmpeg mux, assembly check, rerange patches | deliverable mp4 | references/pipeline.md, references/assembly.md |
| 8 Verify | collision audit, LRC alignment, contact sheet, cut strips, assembly + delivery check | proof images | references/pipeline.md, references/assembly.md, references/lyrics-and-cards.md |
| 9 Atmosphere (optional, re-entrant) | ambient layer stack: sky/water/slow particles that read as weather, not as events | the film's background | references/renderer.md section 4b |

Follow the phases in order and do not skip 8. Phases 3-9 are meant to be re-entered: when the user reports one bad page, patch the renderer, then rerange only the affected frames. Phase 9 is what you re-enter when the note is 「背景很单调」 rather than "this page is wrong" -- it changes every page at once, so it is a full re-render plus the whole proof bundle again.

## Environment (verified on Windows + D:\Anaconda)
- Python: Pillow and numpy only. There is no cv2, av, moviepy, or imageio on a stock Anaconda install; do not plan on them. `imageio_ffmpeg` can be pip-installed if you need a bundled ffmpeg binary: `python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"` returns a real ffmpeg path.
- ffmpeg is usually NOT on PATH on Windows. Find one before designing the pipeline: check `%LOCALAPPDATA%\Microsoft\WinGet\Packages`, `\ms-playwright`, `site-packages\imageio_ffmpeg\binaries`, `C:\ffmpeg`, then `winget install Gyan.FFmpeg`. Store the full path in a variable and use it everywhere.
- Fonts: 霞鹜文楷等宽 (LXGWWenKaiMonoGB-Light/Regular/Medium.ttf) for all code and body text -- the Mono GB variants are the ones with a true 2:1 advance (one Latin glyph = exactly half a CJK glyph), which is what makes the grid snap work. 霞鹜文楷 (LXGWWenKaiGB-Regular.ttf) for prose-ish captions. 得意黑 (SmileySans-Oblique.ttf) for display headlines. All are OFL 1.1; download from the releases of github.com/lxgw/LxgwWenKai and github.com/atelier-anchor/smiley-sans. Do NOT bundle the 25 MB TTFs into a skill or repo. Measured 得意黑 advance: **0.435-0.445 em per CJK glyph** (not 1.0, and not 0.40) -- an N-glyph display line is about 0.44*N*size wide, which is why a "use as few lines as possible" fit collapses a long line to an unreadable size. Fit policy that works: prefer the LARGEST size in AT MOST two lines, and only accept a third row when two rows would drop below ~0.63 of the maximum size.
- Text I/O on Windows: **the default file codec is GBK, not UTF-8.** `open(path)` on the official LRC raises `UnicodeDecodeError: 'gbk' codec can't decode byte 0xae`, and `json.dump` writes mojibake. Pass `encoding="utf-8"` (or `"utf-8-sig"` for a file with a BOM) on every read and write, and `sys.stdout.reconfigure(encoding="utf-8")` in every script that prints CJK.
- Disk: a full song at 30 fps is thousands of PNGs (7831 frames for 4:21). Budget several GB of scratch space and clean the PNG tree after muxing.
- Windows file sandbox: if every tool call dies with `SetNamedSecurityInfoW failed (Win32 5): grantWrite(...)`, that is an ACL precondition failure, not your bug. Ask the user to switch the session to full access (the `diagnose-windows-sandbox-acl` skill documents the same verdict) and continue.
- Windows file sandbox, part 2: a child process (ffmpeg) may be denied writes under the platform temp dir -- the failure reads `Error opening output C:\Users\<you>\AppData\Local\Temp\...\a.raw: Permission denied` and the exit code is 4294967283. `tempfile.mkdtemp()` chooses exactly the denied path, so keep scratch files inside the project (`<project>/_lvstmp`).
- Windows render parallelism: `multiprocessing.Pool` can die with `PermissionError: [WinError 5]` from `multiprocessing/connection.py` (`_winapi.CreateFile`) because `spawn` needs a named pipe. Spawn N independent `subprocess.Popen` workers over disjoint frame ranges instead (see references/pipeline.md), one log each, then wait on every return code.
- PowerShell, two traps that bite in the first five minutes: (a) `Copy-Item`/`Get-Item` treat `[` `]` in a path as a wildcard, so a source file named `...[BV1xxxxxxxxxx].m4a` copies NOTHING and reports no error -- use `-LiteralPath` for every path that contains square brackets; (b) there is no heredoc, and nesting python quotes inside `pwsh -Command "..."` mangles them -- write the code to a `.py` file in the project and run that.

## The house look (what the reference case actually was)
A lyric video for 《反乌托邦》 that rewrites the lyrics as source code: black/white full-bleed alternation, editor/ruler chrome, Chinese identifiers inside valid JS/Python, kaomoji, fake UI widgets, a bottom status bar. It was author-made deterministic text rendering -- proven, not assumed: at t=0 the right diff pane is the left pane shifted by exactly dx=1118 px with mean abs diff 1.85, which no generator produces.

Reusable vocabulary: every page = background layer stack (gradient / mottle / grid / ruler / frame / ghost glyph / ink wash) + perimeter chrome (top bar, status bar, register marks) + a typing code block + one display headline + optional rows/table/log/big-graphic. The alternation of dark and light pages supplies the rhythm; the transition type supplies the punctuation.

## Adapting to a new song
0. Score every LRC you were given against the decoded audio (`assets/timeline_gen.py score`), keep the winner read-only as the timing authority, then derive the page table with `assets/timeline_gen.py build` and its `--check` gate. Do this before writing a renderer: a wrong pick (or a hand-edited cut list) is the single most expensive mistake in this skill. When scoring is inconclusive (identical text, one uniform offset), see non-negotiable 0 -- ask the user and make the revert one copy.
1. Copy `assets/render_prefix.py` and `assets/film_template.py` into a fresh project dir; re-point `BASE`, `T0/T1`, the font paths, and `NFR`. Delete the `shot*` sample pages once your own renderers exist.
2. Parse the LRC into one segment per lyric line with `t0` from the timestamp and `t1` from the next line -- a line that is sung on its own stays its own page even at 1.0 s; only a genuinely blank stamp is card space. Cut the intro: set `T0` at the first sung onset (the reference case used 17.934 s) and build the png sequence from frame 0 of `T0`.
3. Decode the song to 8 kHz mono s16le and build the per-frame envelope; drive every amplitude, ring radius, and visualiser bar from it.
4. Verify each cut sits within 1 frame of a detected onset; if it drifts, re-fit the segment table before rendering a single page.
5. Write the page renderers, then run layout_audit.py, then render EVERY PAGE once at low cost and read the contact sheet, then render the film, then mux, then verify. Fix pages by rerange, never by re-rendering the whole song.
6. Write `out/chunks.json` as each chunk finishes and run `scripts/verify_assembly.py` before muxing; after muxing run `scripts/verify_delivery.py` on the delivered file (and `scripts/verify_short.py` for the vertical one). Both accept `--dry`-style read-only operation: they never modify the project.
7. Copy `assets/lrc_check_example.py` to `<project>/scripts/lrc_check.py` and re-point it at your film module before the first delivery; run it before every delivery after that. Its ORDER check needs the film's own `display()`/draw path, so wire it up while the renderer is fresh in your head, not after.
8. Run `scripts/motion_probe.py` on two or three pages whenever you add or change motion, so the amplitude is a measurement and not a claim.
9. Write the manifest last, from the delivered files (`scripts/delivery_manifest.py`), so the page table it prints is the one that shipped.
